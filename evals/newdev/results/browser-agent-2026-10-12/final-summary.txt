## Clock-skew leeway for timed signatures — pallets/itsdangerous

The patch is ready for manual code review. The automatic advisory review has **not passed** — it timed out on counterexample searches in every attempt and its verdict must be treated as incomplete. The concerns it flagged are listed separately below.

---

### What the patch does

Adds an opt-in `leeway: int = 0` parameter to four methods:

- `TimestampSigner.unsign()`
- `TimestampSigner.validate()`
- `TimedSerializer.loads()`
- `TimedSerializer.loads_unsafe()`

When non-zero, `leeway` widens the acceptance window symmetrically: tokens up to `leeway` seconds past expiry, or up to `leeway` seconds ahead of the verifier's clock, are accepted. Default is `0` — existing behavior is unchanged.

**Files changed:** `src/itsdangerous/timed.py`, `tests/test_itsdangerous/test_timed.py`, `docs/timed.rst`, `CHANGES.rst`

### Policy decisions — all signed by Mira Security

| Decision | Answer |
|---|---|
| Per-call vs constructor | Per-call only (`leeway=0` default on each method, no `__init__` change) |
| Symmetric vs split | Single symmetric value — same seconds both directions |
| Type | `int` only; `bool`/non-int → `TypeError`, negative → `ValueError` |
| Large values | No warning or cap — documented in docstring and docs |
| `leeway > 0` with `max_age=None` | `ValueError` — explicit misuse must not be silent |
| Error message wording | Keep `"< 0 seconds"` — consistent with too-old format |
| `loads_unsafe()` `ValueError` | Propagates — programming error, not bad data |
